# Plug.ai

React, TypeScript, Vite, and Tailwind energy-operations interface.

## BOB chat integration

Without `VITE_BOB_CHAT_ENDPOINT`, chat runs in explicitly labelled preview mode.
Configure this variable with a **same-origin backend path**, such as
`/api/bob/chat`, and restart Vite to enable API-backed responses. The endpoint
is not implemented in this frontend repository. Configure the backend reverse
proxy for development and production before enabling it.

The frontend POSTs JSON with the current conversation and screen context:

```json
{
  "scope": "configuration",
  "siteId": "KUP-SOLAR-001",
  "conversationId": "optional-server-conversation-id",
  "messages": [{ "role": "user", "content": "Explain the reserve policy" }],
  "context": { "config": {}, "phase": "configuring", "activeStep": 3 }
}
```

Return JSON with a non-empty `reply` string and an optional `conversationId`:

```json
{
  "reply": "Your response generated by the API for this conversation.",
  "conversationId": "server-conversation-id"
}
```

All subsequent requests include conversation history. Configuration and
monitoring use separate conversations. Conversation history is retained in
session storage; operational configuration, required test results, activation,
approval deadlines, and audit history are retained in local storage on this
device. These stores are preview persistence, not authoritative backend records.

Messages are rendered as text, never as executable HTML. Loading, HTTP errors,
invalid responses, a 30-second timeout, and retry are handled by the shared chat.
API errors never silently fall back to a fabricated AI answer. Responses are
complete JSON replies; streaming is not implemented.

Store model/API credentials only on the backend, never in `VITE_*` variables.
The backend must authenticate sessions, authorize site access, validate all
client context against authoritative telemetry, enforce freshness and protected
limits, and rate-limit requests. Chat responses are advisory: they cannot change
configuration, grant approval, bypass required simulations, or execute actions.

## Validation

Run `npx tsc --noEmit` and `npm run build`.

## Operational journey

The existing screens use React Router data routing. Portfolio (`/`), AI
recommendations (`/aiRec`), Site (`/siteDetail`), Live overview (`/liveOverview`),
AI actions (`/aiActions`), and Configure BOB (`/bob`) remain reachable through
the shared journey navigation. Add new action opens `/agentChat`; review,
required tests, and final review use `/review`, `/test`, and `/activate`.
Activation requires seven passing results for the current configuration. Edits
invalidate those results without modifying an already activated revision.

The current executable configuration journey is Battery 1 demand support. Other
action-library cards are draft templates, not activated actions. Ask BOB,
action details, audit evidence, protected rules, and the historical work order
have dedicated destinations. All activation, dispatch, and notifications are
explicitly operational previews; this frontend does not command hardware.

The initial scenario is 1 October 2026, 14:32 IST (38 + 6 = 44 MW, SOC 72%).
The explicit 14:50 demand-spike preview uses 52 MW demand and SOC 63% after
18 minutes at 6 MW (1.8 MWh). Grid approval expires after ten elapsed minutes
and persists when navigating or refreshing. Operator approval is blocked;
the permission selector in Audit tests administrator UI behavior only.
Approval never implies execution: a missing grid capability, BOB permission,
freshness evidence, or safety verification keeps actual import at 0 MW. A
verified preview import of 6 MW leaves 2 MW uncovered; 8 MW covers demand.

## Data connections

CSV uploads validate size, quoting, column structure, required field mapping,
SOC range, numeric MW values, and timestamps. The bundled sample is explicitly
historical September 2024 data and never refreshes operational telemetry.

Set `VITE_DATA_CONNECT_ENDPOINT` to a same-origin authenticated server adapter.
The connection screen POSTs `{ siteId, endpoint, apiKey, refreshIntervalMin }`.
Credentials stay in memory and are sent only to this same-origin adapter,
never persisted in browser storage. The adapter must validate upstream URLs,
prevent SSRF, enforce site access, protect keys, and configure durable refresh.
It returns `{ headers: string[], rows: (string | number)[][] }`. Optional
`permissions.gridRemoteAvailable`, `telemetryAgeSeconds`, and
`safetyChecksPassed` provide server-verified preview capability evidence.
Connecting a feed does not grant BOB control: a separate administrator grant
is required in Audit, followed by a new explicit approval. Refresh intervals
over two minutes are monitoring-only for battery execution.

In production, replace local preview persistence and role selection with
server-authoritative authentication, permissions, telemetry, simulation
certification, command acknowledgments, notification delivery, and audit logs.
The chat and data adapter endpoints are contracts, not implementations in this
repository. Configure SPA fallback to `index.html` for direct route loading.
