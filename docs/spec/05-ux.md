# 05 — Application UX

```
 header: product name · nav · sim control (▶ ❚❚ ⏭ speed · inject event) · mode chip · Ask BOB · user
   │
   ├─ Portfolio ──────────── Monitor Sites ──(site row)──────────────┐
   │                            └─(BOB recommendation)──► Actions     │
   ├─ Sites ──► Site page: Site details · Live overview · AI Actions · Maintenance · Activity log
   │               └─(Configure BOB)──► Configure BOB ──(Add action)──► BOB setup wizard (chat + summary)
   │               └─(Run simulation)──► Simulation
   ├─ Actions ── All AI recommendations ──(View evidence)──► Decision panel (side panel)
   ├─ Simulation ── what-if · 24 h replay BOB vs today's practice
   └─ Ask BOB ── drawer everywhere · full-page admin assistant · 📎 upload document
```

The UI follows the Figma screens in `docs/LaGo- Main Version/` and the tokens in [07-design-tokens.md](07-design-tokens.md). This is a demo: the screens are kept as designed except for the seven changes below, each needed to show the brief's intent. Desktop only (1440 px frame).

## The seven changes to the screens

| # | Change | Screens affected |
| --- | --- | --- |
| 1 | A configured action stores BOB's mandate for that action: asset, limits, autonomy, approver, recovery and notifications. The optimiser decides when and how much. "Trigger conditions" are renamed **Watch conditions**. When one is crossed, BOB re-plans and notifies; it is not an if-then command. | Configure BOB, setup wizard, AI Actions tab |
| 2 | "What should this action prioritise?" is replaced by the **portfolio operating mode**, set once by the operator (Settings in the header menu). BOB may switch mode per situation within guard floors, and the mode chip shows the active mode and who set it ("Balanced · operator", "Resilience · BOB"). | Setup wizard step 2, site header chip |
| 3 | **View evidence** opens the decision page (`/decisions/:id`), linked from the BOB recommendation card on the portfolio page and, from P4, from each recommendation: the options BOB compared, the trade-off chart, the stress-test result per option, and BOB's reason. | All AI recommendations, AI Actions tab |
| 4 | **Run simulation** opens the Simulation page. | Site header, portfolio header |
| 5 | The 📎 in BOB chat uploads a document; BOB answers with the extracted constraint, the quoted source line, and Apply / Reject. | BOB chat, admin assistant |
| 6 | "Confidence 94 %" becomes **"Holds in 5 of 6 stress scenarios"**. | All AI recommendations, test step |
| 7 | A **simulation control** in the header: play/pause, step one block, speed (10×, 30×, 60×), sim time (IST), and an "Inject event" menu. | Header (all screens) |

Global clean-up from the token spec also applies: one approve button style (primary), Carbon greys instead of Tailwind greys, 14 px body text, ₹/MWh for prices, our own product name instead of "Tesla Energy / plug.ai", "Kuppam Solar" spelled correctly.

## Screens

### Portfolio overview — `Monitor Sites.pdf`

| Region | Content | Source |
| --- | --- | --- |
| Portfolio cards | Solar, wind, battery: capacity and health (availability %) | `asset`, latest `asset_block` |
| BOB recommendation | Highest-priority open action with reason, operational impact, Approve / Ask BOB | `action` awaiting approval, `cycle.rationale` |
| Registered sites table | Live output vs forecast, storage, grid position, status, AI activity, Open site | `site`, `asset_block`, `forecast`, `action` |
| Transaction history | Executed actions (market trades, battery, curtailment, DR, maintenance) with initiator (BOB or user), amount, value, status. Summary cards: total actions, BOB-initiated, user-initiated, **net saving vs today's practice** (replaces "revenue generated") | `action`, `system_block` of the run and its baseline twin |

### Site page — `Kuppam Solar - Live Overview*.pdf`

Header: site name, status, capacity, mode chip, BOB status, Run simulation, Configure BOB.

| Tab | Content |
| --- | --- |
| Site details | Assets at the site with their parameters (read-only); location; commissioning date |
| Live overview | Weather strip; generation, demand, battery and grid cards; balance statement; alert banner; **generation and demand chart: actuals to NOW, then BOB's planned next 24 h with the P10–P90 band**; conditions, active alerts, data sources; energy flow; battery storage |
| AI Actions | Currently executing (with step progress); Pending approval (approve / modify / reject, time remaining); **Watch conditions** (each threshold, current value, met or not, last triggered) |
| Maintenance | Tasks with window and deadline; BOB's proposed moves with lost-value estimate; inspection proposals; approve or reject |
| Activity log | This site's audit entries, newest first |

### Actions — `All AI recommendations.pdf`

Cards for open actions sorted by priority: site, title, "Why BOB recommends this", suggested action, operational impact, stress-test result (change 6), freshness, Ask BOB, **View evidence** (change 3), Open site, Review approval. "Other recommendations" lists executing, recommend-only and dismissed items.

### Decision panel (new, right side panel)

One cycle, top to bottom: what triggered it → operating mode and why → options (3–5 cards with their actions and KPIs) → trade-off chart (cost vs carbon, point size = reserve, chosen option marked) → stress-test grid (option × scenario, worst-case regret in ₹) → BOB's reason → actions with approval status. Opens over any page; closes back to it.

### Configure BOB — `configure-bob.pdf`

The list of configured actions for a site: toggle active/paused; **Watch conditions** (change 1); execution rules (auto up to, approval above, max per day, cooldown, reserve); recent activity; today's summary; Edit opens the wizard.

### BOB setup wizard — `BOB Chat — 1 … 12.pdf`

Steps as designed: Select action → Configure → Test → Activate, with the chat on the left and the configured-actions summary on the right.

- Configure decisions: controlled asset, watch conditions, safety limits, automation and approval (approver, response time, escalation, expiry behaviour), recovery, notifications. The "prioritise" step is replaced by a read-only line showing the portfolio mode with a link to change it (change 2).
- Protected limits come from the portfolio's protected settings (seed data) and show as locked. Asking BOB to breach one returns the "Safety rule blocked action" card (screen 12).
- BOB can fill any field from chat; the form values are the source of truth, and nothing takes effect until **Activate**.
- Test runs the simulator scenarios shown (current conditions, battery unavailable, low charge, high temperature, higher demand, delayed data). Activation requires the three marked required scenarios to pass.
- Change review (screen 7) shows the diff against the active version before activation.

### Ask BOB — drawer and `BOB Admin Chat — 11. Operational Overview.pdf`

Suggested questions; operational summary cards; recommended follow-ups with deep links. 📎 upload (change 5) returns an extraction card: constraint, targets, time window, quoted line, "tightens a limit → applied automatically" or "needs your confirmation", Apply / Reject.

### Simulation (new)

- **What-if:** pick changes (asset out, line limit, demand %, renewables %, price %, mode) → current plan vs what-if plan, side by side, with the cost, carbon, curtailment and reserve differences.
- **24 h replay:** preset scenario and number of seeds → BOB vs today's practice per metric (box plots) plus the reliability summary (hard-limit violations, fallbacks, BOB call success).

### Connect data source — `Connect Data Source — CSV or API.pdf` (mock)

CSV upload with fixed known column names (preview and type detection as designed) imports history for a site; "Test connection" for API answers from the simulator. No real external connections.

## Header simulation control

Run picker (new run from a preset) · ▶ / ❚❚ · ⏭ one block · speed · sim time and block · "Catching up" while a cycle overruns · Inject event (cloud bank, wind ramp, price spike, battery trip, line derate, demand surge, frequency dip) with a small parameter form.

## Demo click path (~6 minutes)

1. New run → `demo_story` → play at 30×. Portfolio overview fills; net saving vs today's practice is already positive from the morning.
2. 11:07 cloud bank → toast → Kuppam Solar Live overview: below-forecast banner; chart shows the revised plan after NOW.
3. Actions → the new recommendation → **View evidence**: options, trade-off chart, stress-test grid, BOB's reason.
4. 11:10 price spike → mode chip changes to "Economic · BOB"; the plan holds battery energy for the evening.
5. 11:12 Battery 2 trips → pending approval for a demand-response call → approve on the AI Actions tab → executing with step progress.
6. 11:14 north corridor derate → wind curtailed only for the remainder; activity log shows why.
7. 11:20 Ask BOB → 📎 upload the storm bulletin → constraint applied with its quote → mode "Resilience · BOB"; Maintenance tab shows the wind job moved and an inspection proposed.
8. Configure BOB → Add action → wizard: set limits, test the three required scenarios, activate.
9. Simulation → replay 20 seeds → BOB vs today's practice.

## States

Every data view has loading (Carbon skeleton), empty ("no run yet — start one"), stale (feed lag > 10 s shows a banner) and error (the API's `detail`) states. Polling pauses when the tab is hidden.
